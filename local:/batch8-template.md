# Money Protocol Template for Cybersecurity Skills

Each rewrite MUST follow this exact structure. Every section below is REQUIRED.

## Frontmatter
Keep existing name, description, domain. Add `money` tag to tags list.

## Body Structure (in order):

### Overview (existing — rewrite domain-appropriate)
### When to Use + When NOT to Use (keep existing)
### Money-Making Overview (REQUIRED — see format below)
### First Action in 60 Minutes (REQUIRED — real runnable script)
### Deliverable Format (REQUIRED — concrete output template)
### Anti-Rationalization (REQUIRED — domain-specific table)
### Workflow / Process (keep existing steps)

## Money-Making Overview Format:
```
## Money-Making Overview

**Target Buyer:** [Who pays for this specifically]

**How You Make Money:**
1. [Service 1 — concrete, with price range]
2. [Service 2]
3. [Service 3]

### Service Tiers
| Tier | Price | What They Get |
|------|-------|---------------|
| **Basic** — [Name] | $[price] | [description] |
| **Pro** — [Name] | $[price] | [description] |
| **Enterprise** — [Name] | $[price]/mo | [description] |

**Expected First Dollar:** [realistic timeline]
```

## First Action in 60 Minutes Format:
A real bash/python script that can run on Kali Linux. It must:
- Accept a target as argument
- Use tools available on Kali or installable via apt/pip
- Produce a deliverable file
- End with a summary of what was generated

## Deliverable Format:
A concrete template showing what the client receives.

## Anti-Rationalization Table:
Domain-specific excuses vs reality. At least 5 rows.

## IMPORTANT RULES:
- NO generic text — every sentence must be action-specific
- NO placeholders like "[insert your tool]" — use real tool names
- Scripts MUST use real CLI tools (nmap, metasploit, hashcat, etc.)
- Prices must be realistic for Kali+RTX 2060 SUPER user
- Expected First Dollar within the skill's domain
- NO "see parent skill" — this IS the skill
