# Docker Compose — Deep Reference
## When to Use
Docker Compose when you need to run multiple containers that work together — a web app with a database, a cache, a queue, or all of them at once. It replaces `docker run -d --name ...` chains with a single declarative file and one command. Use it for:- **Local development environments** that must match production (same Postgres, Redis, queue versions)- **Integration testing** — spin up real dependencies (DB, message broker, API mock) in CI, then tear them down cleanly- **Microservice setups** where 3–10 services need to communicate over a shared network- **Onboarding new developers** — they run `docker compose up -d --wait` instead of installing 5 databases and debugging connection strings- **Reproducible demos** — reviewers or stakeholders run the same environment with zero setupDo NOT use Compose for: production orchestration at scale (use Kubernetes or Nomad), single-process containers (plain `Dockerfile` + `docker run` is simpler), or ephemeral CI helpers that don't need networking between containers (a Docker-based GitHub Action step is lighter).## Structural AnatomyA `compose.yml` has three top-level blocks. Every field has a purpose:```yamlservices:   # ← each service = one container api:   image: postgres:16-alpine        # image to run   build: ./docker/api              # OR build from Dockerfile   container_name: my-api           # explicit name (omit for scaling)   ports:     - "8000:8000"                  # host:container   expose:     - "8000"                       # internal-only, no host mapping   volumes:     - pgdata:/var/lib/postgresql/data   # named volume     - ./src:/app                        # bind mount (dev hot-reload)     - /app/node_modules                 # anonymous (prevents overwrite)   environment:     - DB_HOST=db                        # literal string     - DB_PORT=${DB_PORT:-5432}          # from .env or default   env_file: ./config/db.env             # or from file   depends_on:     db: { condition: service_healthy }  # wait for health, not just start   healthcheck:                          # crucial for depends_on chains     test: ["CMD", "pg_isready"]     interval: 5s     timeout: 3s     retries: 5     start_period: 10s                   # grace before first check   restart: unless-stopped              # always, on-failure, no   networks:     - backend   logging:     driver: "json-file"     options:       max-size: "10m"       max-file: "3"networks:     # ← service-to-service communication backend:    # default bridge (internal)   driver: bridge   ipam:     config:       - subnet: 172.20.0.0/16 frontend:   # external-accessible   driver: bridgevolumes:      # ← persistent data, survives container recreation pgdata:     # named, driver-local by default redis-data:   driver: local cache:      # used for tmpfs speed   driver_opts:     type: tmpfs     device: tmpfs```**Key rules of thumb:**- One service per concern — don't stuff two processes into one container- Named volumes for data that must survive `down`; bind mounts for code that must hot-reload- `depends_on` alone is NOT enough — add `condition: service_healthy` with a real healthcheck- Use `.env` for secrets-in-development; never commit production secrets- `restart: unless-stopped` on databases, `restart: no` on one-shot jobs---

## Multi-Profile Compose: Dev vs ProdUse separate compose files with `extends` or compose profiles for environment-specific configuration:```yaml# compose.dev.yml — overrides for local developmentservices: api:   build:     target: development   volumes:     - .:/app   environment:     - LOG_LEVEL=debug   ports:     - "${API_PORT:-8000}:8000" db:   ports:     - "5432:5432"              # expose for local tools (pgadmin, dbeaver) redis:   ports:     - "6379:6379" adminer:                        # dev-only: DB admin UI   image: adminer   ports:     - "8080:8080"   depends_on:     db:       condition: service_healthy``````yaml# compose.prod.yml — overrides for production deploymentservices: api:   build:     target: production   restart: always   deploy:     replicas: 2                 # scale with swarm or compose up --scale   environment:     - LOG_LEVEL=warning db:   restart: always   volumes:     - pgdata:/var/lib/postgresql/data     - ./backups:/backups redis:   restart: always nginx:                          # prod-only: reverse proxy + TLS   image: nginx:alpine   ports:     - "80:80"     - "443:443"   volumes:     - ./nginx.conf:/etc/nginx/nginx.conf:ro     - ./certs:/etc/nginx/certs:ro   depends_on:     - api```**Invocation:**```bash# use -f flag to compose multiple files (later files override earlier)docker compose -f compose.yml -f compose.dev.yml up -d     # devdocker compose -f compose.yml -f compose.prod.yml up -d   # prod```**Or use profiles** for simpler dev-vs-prod within one file:```yaml# compose.yml excerpt with profilesservices: adminer:   image: adminer   profiles: ["dev"]          # ← only starts with --profile dev   ports: ["8080:8080"] nginx:   image: nginx:alpine   profiles: ["prod"]   ports: ["80:80", "443:443"] api:                         # no profile → always included   # ...``````bashdocker compose --profile dev up -d    # api + db + redis + adminerdocker compose --profile prod up -d   # api + db + redis + nginx```---
## Workflow

--|| **Define** | `touch compose.yml` + edit | Declare services, networks, volumes || **Build** | `docker compose build` | Build images (or skip: `up` auto-builds) || **Up** | `docker compose up -d` | Start all services detached || **Up (wait)** | `docker compose up -d --wait --wait-timeout 60` | Start + wait for healthchecks || **Up (rebuild)** | `docker compose up -d --build` | Rebuild images then start || **Debug** | `docker compose logs -f api` | Tail logs for one service || **Debug** | `docker compose exec api sh` | Interactive shell in running container || **Debug** | `docker compose ps` | Show status and ports || **Debug** | `docker compose top` | Show running processes per service || **Down** | `docker compose down` | Stop + remove containers and default network || **Down** | `docker compose down -v` | Also delete named volumes (⚠️ data loss) || **Reset** | `docker compose down -v && docker compose up -d` | Full reset from scratch |### Debugging patterns```bash# See WHY a container exiteddocker compose logs <service># Check healthcheck statedocker compose psdocker inspect $(docker compose ps -q api) | jq '.[].State.Health'# Enter a container safely (even if entrypoint failed)docker compose run --rm api sh# Run a one-off commanddocker compose run --rm api python manage.py migrate# Copy files out of a containerdocker cp $(docker compose ps -q api):/app/logs/app.log .# Trace network: verify service reachabilitydocker compose exec api ping dbdocker compose exec redis redis-cli ping# Rebuild a single service without touching othersdocker compose build apidocker compose up -d api# Export running config (for debugging merge order)docker compose config```### .env file pattern```bash# .env — loaded automatically by docker compose (commit example, keep real secrets local)API_PORT=8000POSTGRES_PASSWORD=dev_only_change_in_prodLOG_LEVEL=debugBUILD_TARGET=development```---
## Common Pitfalls| Pitfall | Symptom | Fix ||---
----
--|---
----
--|---
--|| Missing `.env` | Services start with empty env vars | Create `.env` or set all vars explicitly || No healthcheck on `depends_on` | Race: app starts before DB is ready | Add `healthcheck` + `condition: service_healthy` || Bind mount overwrites container files | `node_modules` / `__pycache__` missing | Add anonymous volume: `- /app/node_modules` || Port conflict | `Error starting userland proxy: listen tcp4 :8000: bind: address already in use` | Change port mapping or stop other process || Windows CRLF in scripts | `exec ./entrypoint.sh: no such file or directory` with a readable file | Run `sed -i 's/\r$//' entrypoint.sh` || Forgot `--wait` | App crashes in CI because DB not ready | `docker compose up -d --wait` |---
## Anti-Rationalization Table

| Rationalization | Reality |
|---|---|
|| "I'll just install Postgres locally, Docker is overkill" | Two months later you need Redis too, then a queue — now your laptop has 6 services fighting for ports. Compose isolates dependencies per-project with one command. || "docker-compose.yml is just syntax, I'll wing it" | A missing healthcheck causes a 3-hour debug session because the app starts before the DB. Wrong volume mount deletes production data. Every field serves a purpose. || "I'll use the same compose.yml for dev and prod" | Exposing dev ports (adminer, DB on 5432) in prod is a security hole. Different TLS, logging, scale, and restart policies. Split files or use profiles. || "I can skip .env files, just hardcode the values" | Now you can't commit compose.yml to a team repo without leaking passwords. `.env` is gitignored; `compose.yml` is committed. || "My app works locally, compose is just extra complexity" | The CI server, teammate's Mac, and the staging box all run different OS versions. Compose is the reproducible environment contract across every machine. |---
